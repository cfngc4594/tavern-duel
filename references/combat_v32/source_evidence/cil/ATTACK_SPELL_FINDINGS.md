Source visuals: 37.0.0.255130.254477. Rules stay 5834. No original client was run. REA 6.8 inspect of the large Assembly-CSharp DLL returned partial output due its 64 MiB metadata/result budget; CIL fallback used the already installed dnfile/dncil. Do not call that a complete REA decompile.

## Final supplemental runtime evidence

### Packed original MinionShake tracks

The restored addon manifest is `../TavernDuel/assets/original_combat_shake_v32/manifest.json`. `decode_minion_shake.py` reads its 13 original AnimationClips without running the client. `minion_shake_runtime.json` retains all original controller data and decodes all seven streamed scalar channels in generic binding order: position XYZ then quaternion XYZW. There are no dense or constant channels in these clips. CRC32("Card_Play_Ally") is 2468927693, exactly the original binding path hash. Every key contains original float32 cubic coefficients, evaluated as `((a*dt+b)*dt+c)*dt+d`, where dt is time since that channel's preceding key. All adjacent finite endpoints agree within 7.54e-7. Each clip has its own original stop time; there is no uniform duration per shake size. The controller leaf m_Duration is retained but must not replace the AnimationClip stop time.

The controller has Idle and Minion Shake Blend Tree states. It drives a type2 two-dimensional blend tree with posx/posy, 12 cardinal samples at magnitudes .1/.5/1. Idle-to-shake is conditioned on shake=true, duration1.0, no exit-time requirement, normalized duration. Shake-to-Idle has exitTime=.5, duration=.491143167, normalized duration. The packed clips and state settings are recovered, but Unity's native Animator blend-weight and transition-normalization kernel is not present in the managed DLL. A separate-engine implementation must honestly identify that kernel and coordinate/render projection as compatibility work rather than claim original client pixel/frame identity.

### Camera shake

`animate_camera_semantics.cil.*`: MainCameraShakerAction0x06016be0 calls CameraShakeMgr.Shake(camera,amount,time)0x06015082. This constructs AnimationCurve.Linear(0,1,time,0), so this action has linear intensity decay. UpdateShake0x06015088 independently samples uniform [-amount.axis*intensity,+amount.axis*intensity] each update and adds to the saved initial camera position. It is not a sine or fixed-rate oscillation. StartShake0x06015086 ignores smaller new amount.sqrMagnitude unless override, and ignores a new shake while a current override is active. Visual randomness must stay separate from the local 5834 rules RNG.

### AnimateFloatV2 / AnimateColor

`animate_action_semantics.cil.*` is extracted from Blizzard.T5.PlayMaker.Runtime.dll, not Assembly-CSharp. AnimateFsmAction.UpdateAnimation0x060000ca implements calculation 0=initial,1=curve,2=initial+curve,3=initial-curve,4=curve-initial,5=initial*curve,6=initial/curve,7=curve/initial. A zero denominator returns float.MaxValue. Initial values are captured once on entry. No min/max clamp exists in these actions. With explicit time, evaluation argument is currentTime/time*lastKeyTime; with time=None it is currentTime. UpdateTime0x060000c9 increments by frame delta or realtime delta multiplied by speed (None=1). CheckStart0x060000c8 decrements delay until below zero before starting, so a frame boundary can separate serialized zero delay and first update. ignoreCurveOffset sets initial currentTime to firstKeyTime, scaled by time/lastKeyTime when time is explicit. CheckFinished0x060000cb waits for all channel end times; the V2/Color action emits Finish/event on the next update after final assignment. Looping post-wrap modes do not complete. AnimateColor applies independent curves/calculations to RGBA. Legacy AnimateFloat differs: OnEnter0x060000bc writes curve.Evaluate(0), OnUpdate0x060000bd writes at currentTime and handles its own completion.

### Sequential Arcane Missiles and atomic rules

OnMissileTargetReached0x06014b28 starts SpawnImpact at IL002b, immediately calls SpawnMissileInSequence at IL004e when no chain and SpawnInSequence=true, then activates the arriving missile's Death at IL0054. It does not wait for the impact metadata GameDelay. For EX1_277 the second launch therefore precedes the first delayed damage presentation. A safe local adapter resolves the existing atomic rules once at launch, records their actual targets and per-hit board snapshots, then presents those snapshots at independently accumulated source flight-arrival plus metadata-delay times. It must neither reroll targets nor resolve the full spell once per visual missile. `atomic_compat_dispatch.json` contains source presentation points, not authority to change atomic rules or reproduce the server metadata system.

## RTT pass selection follow-up

`render_command_lists.cil.*` and `render_pass_selection.json` prove ordinary RGB capture does not blindly use pass0 or every pass. RenderCommandLists.AppendRenderCommands0x060154a6 IL0201..02c1 scans Material.passCount and Shader.FindPassTagValue(pass,"LightMode"). Missing tag becomes SRPDefaultUnlit. The allowed categories (cctor0x060154a7) are SRPDefaultUnlit, UniversalForward, LightweightForward, in that output order. Only the first occurrence of each category is stored; every found category is emitted, at most three commands per material/submesh. No matching category means no command, not a pass0 fallback. GlowTransparent and explicit Alpha LightModes are excluded. RenderToTexture.RenderTex0x060153ca passes false to Pool.Get at IL00ef; this bool is includeInactiveRenderers, not a glow selector. RenderBloom0x060153cb also builds the same command list and uses a null replacement shader, so its specialized RTT bloom is not the main-scene GlowTransparent pass.

Commands split into opaque renderQueue<3000 and transparent>=3000, each sorted by renderer.sortingOrder then material.renderQueue (0x060154a4), not camera depth. DrawCommand0x060154ac checks layer mask and renderer.enabled then draws exact command.passIndex. A replacement-shader capture starts from the same command lists, filters a material-level replacement tag, and calls a different DrawRenderer overload without forwarding the selected passIndex (0x060154ad). This trace does not establish the native default-pass value of that overload. It also does not establish the main-scene custom glow compositor; secondary GlowTransparent passes must remain independent rather than automatically attached to ordinary RGB capture.

The original RTT plane triangle indices are [3,1,2,2,1,0], directly read as six little-endian int32 values from Assembly-CSharp FieldRVA0x85d28b for field token0x04016684. Raw bytes and field identity are in rtt_plane_triangles.json. Any winding correction for a negative-determinant Unity-to-Godot coordinate transform belongs in the explicit compatibility bridge.
