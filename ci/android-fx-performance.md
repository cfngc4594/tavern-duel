# Android 法术与结算性能

## 测试方法

使用 V2509A（Android 16，Mali-G1-Ultra MC12）和 Godot 4.7.1 ARM64 Release。短测固定按火球术、幸运币、胜利结算的顺序，在同一进程各触发两次。火球术通过实际出牌造成 6 点伤害，手牌幸运币提供 1 点临时法力，终局均获胜。各组的六项玩法结果完全一致。开局发放硬币的动画由另一条路径负责。

下表的首次安装使用不同的应用包名。系统与驱动层缓存仍可能跨应用共享，测量顺序与电池温度也有差异。同一个 APK 依次重启五次，用于比较应用缓存已有的状态。手机在测量前关闭面板并保持唤醒。帧间隔来自 Godot 循环，渲染区间来自 `frame_pre_draw` 和 `frame_post_draw`，包含命令提交和等待。Compatibility 后端的视口数据为渲染线程 CPU 时间。

## 短场景 A/B

各单元格为首次 / 重复触发的最大帧间隔，单位 ms。

| 阶段 | 新装原路径 | 新装仅去火球光晕 | 新装轻量路径 | 缓存后原路径 | 缓存后轻量路径 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 火球术 | 1,725 / 259 | 1,617 / 291 | 865 / 272 | 305 / 276 | 286 / 235 |
| 手牌幸运币 | 942 / 180 | 1,072 / 197 | 556 / 231 | 143 / 152 | 134 / 135 |
| 英雄死亡动画 | 998 / 192 | 1,064 / 200 | 1,000 / 166 | 186 / 193 | 182 / 185 |
| 结算画面 | 601 / 214 | 665 / 224 | 514 / 187 | 294 / 215 | 271 / 196 |

新装原路径、仅去光晕和轻量路径的电池起始温度分别为 32.0、34.2 和 33.6 °C。缓存后原路径和轻量路径分别为 33.2 和 32.8 °C。同 APK 中另一轮轻量路径的火球术为 308 / 245 ms，幸运币为 137 / 141 ms。

| 路径 | 变更和依据 |
| --- | --- |
| 火球术 | 起手、飞行、命中各去掉 9 个离屏捕获和光晕视口，用同一着色器直接绘制对应火光。保留原施法位置、弹道、命中反馈和音效。仅去光晕仍需每阶段 3 个视口，新装最大帧为 1.62 秒。采用直接绘制后，缓存组的重复触发绘制调用中位数从 305 降到 268。 |
| 手牌幸运币 | 用直接绘制的金色光效替代 3 个离屏捕获视口。缓存组首次触发的绘制调用中位数从 298 降到 280。新装组首次最大帧改善，第二次触发有 152 ms 的额外渲染尖峰，整局数据用来核对实际使用路径。 |
| 结算背景 | 用屏幕拷贝与一遍模糊、去色和暗角替代 9 个背景视口，保留结算内容的两个视口及继续按钮。新装首次背景创建脚本耗时从 24.05 降到 2.39 ms，缓存组从 23.84 降到 1.65 ms。模糊半径和细节使用轻量近似。 |
| 连续粒子速度 | 在进入状态时查找一次播放速度的目标，后续帧复用同一条清单记录并继续计算该帧的速度。Mac 无头隔离测量中，幸运币四个目标的查找与分派从约 1.6 ms/帧降到约 0.004 ms/帧。整局包包含此变更。 |

新装轻量路径的火球术最大帧为 865 ms，其中渲染区间 597 ms，游戏脚本 264 ms。该路径的重复火球术最大帧 272 ms，其中游戏脚本约 268 ms。幸运币首次最大帧的渲染区间为 469 ms。英雄死亡最大帧的渲染区间为 872 ms，游戏脚本约 127 ms，早于结算背景创建。立即重复死亡动画时，视口渲染线程的峰值明显下降，首次提交涉及的具体材质仍待隔离。

胜利动画另测了省略三个装饰烟花的方案。首次爆裂的最大帧为 1,089 ms，其中渲染区间 968 ms。重复爆裂最大帧从 166 降到 74 ms，结算画面从 187 降到 70 ms。胜利碎裂、闪光、烟雾、弹坑和音频保留。无头回归确认结算帧、烟雾的随机种子以及失败、平局的事件序列一致。

真机特效脚本明细显示，火球术飞行采样有一帧耗时 151 ms，其中粒子推进占 150 ms。直接绘制成功后，仅跳过原本只供离屏捕获使用的九个装饰发射器的粒子模拟。保留发射器创建顺序、种子、速度和停止指令，未被替代的粒子继续运行。新装短测的火球飞行粒子推进峰值降到 35 ms，重复释放的最大帧从 280 降到 94 ms，首次释放最大帧从 915 降到 782 ms。手牌幸运币对应阶段的脚本采样最大值从 106 降到 36 ms，首次触发仍受先发生的渲染尖峰影响。

英雄爆裂的独立对照在启动时用原棋盘与透射视口预绘制一块英雄碎片和一个弹坑。原始网格、材质和着色器变体在隐藏的加载阶段提交，临时对象随即移除。两批预绘制增加 906 ms 加载时间，首次爆裂最大帧从 1,089 降到 471 ms，其中渲染区间从 968 降到 353 ms。主棋盘视口 CPU 峰值由 617 降到 277 ms，透射视口由 349 降到 78 ms。两轮起始电池温度为 36.4 和 36.5 °C，均使用简化烟花。重复爆裂最大帧为 74 和 78 ms。这个预热覆盖英雄碎片和弹坑，首次出现的其他材质仍有单独的成本。 [Godot 着色器管线文档](https://docs.godotengine.org/en/stable/tutorials/performance/pipeline_compilations.html)

本轮原特效对照和直接绘制版使用相同的脚本、缓存实现和采集代码，分别在新应用包中测量。两轮电池起始温度为 36.4 和 35.7 °C，上一版为 33.4 °C。本轮两组的整局循环速率与 P99 接近，主要改善发生在两个目标法术。上一版数据保留为历史对照。

最终组合新增装饰粒子裁剪和两批预热，电池起始温度为 36.2 °C，整局共采集 4,432 个连续帧。游戏脚本平均从本轮对照的 30.34 降到 29.11 ms，渲染区间中位数从 3.02 降到 2.86 ms，P95 从 14.56 变为 14.67 ms。火球术最大帧的游戏脚本从直接绘制版的 281 降到 100 ms，渲染区间仍为 246 ms。幸运币最大帧的渲染区间约 448 ms，结算最大帧的渲染区间从对照的约 921 降到 348 ms。预热在加载阶段占 894 ms，渲染内存峰值增加约 6.84 MiB。

最终组合仍未达到整局稳定 30 FPS。开场发牌、对手法术和抽牌的最大帧分别为 929、924 和 907 ms，三个慢帧的渲染区间分别为 802、814 和 781 ms。黑屏测试获得了应用循环时序。SurfaceFlinger 对应游戏层的 4,490 个呈现间隔记录均为 0 ms，亮屏呈现节奏与特效外观仍待核对。

Android CI 的 44 项无头回归通过，覆盖直绘路由、粒子边界、胜利事件顺序和预热后临时对象释放。试玩 APK 与真机整局诊断包使用相同的项目设置、脚本、资源和引擎库。 [短测 JSON](../build/android-perf/fx-device-comparison.json) · [整局 JSON](../build/android-perf/fx-whole-match-comparison.json) · [试玩 APK](../build/android-perf/TavernDuel-Android-Optimized.apk)

## 复跑

完整对局导出参数为 `-- --android-match-benchmark --android-match-profile --startup-timing`。短测改用 `-- --android-match-benchmark --android-match-profile --android-fx-benchmark --android-fx-ab-order=reference,no_bloom,candidate,candidate,reference --android-fx-viewport-profile`。同一安装包每次完整跑完后轮换分组。独立新装短测使用单项分组。用 `python3 ci/analyze_android_match.py reference.log candidate.log` 分析连续帧记录。试玩包省略全部诊断参数。

部分系统会省略应用 logcat 输出。诊断包可加 `--android-match-output=/sdcard/Android/data/<包名>/files/android-match.log`，由应用结束测量后写入本次基准记录，再用 `adb pull` 导出。短测可加 `--android-fx-profile-effects`，在结束后输出法术采样的粒子、调度和渲染准备耗时。
